## 4b. Inference time (hidden test, ~1,300 studies, Kaggle T4 + 4 CPUs)
* DICOM preprocessing dominates: 1.05–1.5 s/study → 23–32 min, paid once.
* Each EfficientNet-B0 fold adds ~1.5–2 min; 1 fold ≈ 25–35 min, 5 folds ≈ 32–45 min
  (observed submit→scored ≲ 32 min for EXP-007 and ≲ 30 min for EXP-009). ~12× headroom under the 9 h limit.

Ideas to make inference faster / better (ranked):
1. **Decode only the slices we keep** — read headers of all slices (`stop_before_pixels`) to sort by position, then
   decode pixels for the 72 sampled slices only (we currently decode every slice, ~165/study) → ~2× faster preprocessing.
2. **Threaded DICOM reads + raw PixelData decode** for uncompressed files (forum 743374: pydicom 1.2 → 0.3 ms/slice,
   16 threads 6× read throughput) → preprocessing toward ~10 min.
3. **Overlap CPU preprocessing with GPU inference** — predict each study as soon as its cache is written instead of
   caching all 1,300 first.
4. **One data pass for all checkpoints** — load each study's windows once and run every fold/model on that batch
   (today each checkpoint re-reads the cache) → model cost ≈ 1 fold instead of N.
5. **Use both T4s** (GPU notebooks have 2) — shard studies across GPUs / one model per GPU.
6. Accuracy, not speed: evaluate **more windows per study** (k_eval 48 → all ~66 valid centres) on fold-0 OOF first;
   Raptor reported +0.003–0.006 from denser eval windows. Cheap because models are not the bottleneck.
7. Efficiency track: a single fold (LB 0.907) at ~25 min is already a reasonable efficiency-prize candidate; ideas 1–4
   could bring it near ~10 min.
